Architecture

Joltv is built in Rust and separates the user experience, dependency resolution, compilation, and packaging into focused modules.

Overview

CLI (clap)
  └── main.rs: command orchestration
       ├── core: manifests, lockfile, and cache
       ├── resolver: Maven Central and POMs
       ├── build: javac, execution, and JUnit
       ├── packaging: JARs, jpackage, installers
       ├── toolchain: JDK discovery and downloads
       ├── scaffold: templates and IDE config
       └── doctor: environment diagnostics

Main modules

ModuleResponsibilityKey files
coreCanonical types and persistence.manifest.rs, lockfile.rs, cache.rs
cliCommands, arguments, and flags.args.rs, mod.rs
buildCompilation, execution, and tests.compiler.rs, runner.rs, test_runner.rs
resolverMaven downloads and analysis.maven_client.rs, pom_parser.rs
packagingDistributable artifacts.jar.rs, jpackage.rs
toolchainLocal and remote JDKs.detector.rs, downloader.rs

Execution flow

  1. Clap parses the command and its options.
  2. The manifest is loaded from the current directory or workspace root.
  3. The toolchain manager selects a compatible JDK.
  4. The resolver prepares dependencies and the build invokes Java tools.
  5. The result is written to target/ or dist/.

Extending the CLI

Declare new command interfaces in src/cli/args.rs, keep behavior in the appropriate domain module, and expose public APIs through its mod.rs. Avoid placing compilation or packaging logic directly in main.rs.
