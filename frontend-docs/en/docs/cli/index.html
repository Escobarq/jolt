CLI reference

This page documents the commands accepted by the jolt executable, including aliases, short flags, values, and defaults.

Source of truth: the help output from your installation always takes precedence. Run jolt --version and jolt <command> --help when your version differs.

Syntax and help

jolt <command> [options] [arguments]
jolt --version
jolt --help
jolt build --help

Positional arguments are required unless stated otherwise. Boolean flags are enabled by writing them; they do not take true or false.

Adding a dependency step by step

Use groupId:artifactId to let Jolt resolve the version, or append :version to pin it explicitly. The --dev flag (-D) writes the dependency to [dev-dependencies]; this is different from a runtime dependency.

# Runtime: required when the application runs
jolt add com.google.code.gson:gson

# Development/testing: added to [dev-dependencies]
jolt add org.junit.jupiter:junit-jupiter-api:5.11.0 --dev
# Equivalent short form:
jolt add org.junit.jupiter:junit-jupiter-api -D

# Confirm that it was written to the correct section
Select-String -Path jolt.toml -Pattern "dev-dependencies|junit"

After adding it, run jolt install to resolve and download the dependency tree. Jolt updates jolt.toml and creates or updates jolt.lock; keep that lockfile under version control.

jolt add org.junit.jupiter:junit-jupiter-engine:5.11.0 --dev
jolt install
jolt test
Which command should I use? Use a normal dependency for libraries your application needs in production. Use --dev for JUnit, Mockito, analysis tools, or any library used only during development and testing.

Dependencies inside a workspace

From a workspace root, select the module with --member (or its --pkg alias). The module must exist in the workspace manifest.

# Runtime dependency for the api module
jolt add com.fasterxml.jackson.core:jackson-databind --member api

# Test dependency for the api module
jolt add org.junit.jupiter:junit-jupiter-api:5.11.0 --dev --member api

# Install every module
jolt install --all

Search and remove

# Search Maven Central (10 results by default)
jolt search junit
jolt search junit --limit 20

# Remove a dependency; omit the version
jolt remove com.google.code.gson:gson
# Equivalent alias
jolt rm com.google.code.gson:gson

Important: remove takes only groupId:artifactId. If the dependency belongs to a module, pass the selector again: jolt remove org.junit.jupiter:junit-jupiter-api --member api. There is no separate “update” command: change the version in jolt.toml and run jolt install again.

package also accepts the aliases pkg and bundle. In build, --package delegates to native packaging; do not confuse it with the --package value used by init.
