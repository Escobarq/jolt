Jolt · Guide

Configuration

The jolt.toml file describes project identity, Java version, dependencies, and packaging behavior.

Recommendation: keep jolt.lock under version control for repeatable dependency resolution.

Minimal manifest

[project]
name = "my-app"
version = "1.0.0"
java_version = "21"
main_class = "com.example.App"
package = "com.example"

[dependencies]
"com.google.code.gson:gson" = "2.14.0"
FieldDescription
nameProject name and default artifact name.
versionVersion used by builds and packages.
java_versionRequired JDK major version; Java 21 is the default.
main_classClass containing the application main method.
packageRoot Java namespace for templates and scaffolding.

Dependencies

Coordinates use Maven notation: groupId:artifactId, optionally followed by a version.

[dependencies]
"org.apache.commons:commons-lang3" = "3.17.0"
"org.openjfx:javafx-controls" = "21.0.2:windows"

[dev-dependencies]
"org.junit.jupiter:junit-jupiter-api" = "5.11.0"

Regular dependencies are available at runtime. Development dependencies are reserved for tests and tooling.

Packaging

[package]
type = "nsis"
name = "MyApplication"
dest = "dist"

[package.windows]
upx = true
add_to_path = true
desktop_shortcut = true
