Jolt · Guide

Quick start

This is the general guide: install Jolt, confirm that it works, create a Java project, and follow the complete flow through tests and artifact generation.

Conventions: run commands from a terminal. On Windows, you can use PowerShell; on macOS/Linux, use a Bash-compatible terminal. jolt is the project's actual executable.

What is Jolt?

Jolt is a Java project tool that centralizes project creation, Maven dependencies, compilation, execution, testing, and packaging. The jolt.toml file describes the project, while jolt.lock pins resolved versions.

Install

Get the CLI through Cargo and verify the executable.

Create

Generate a project with a template and Java namespace.

Ship

Run, test, compile, or package your application.

1. Requirements

ToolPurposeCheck
Rust and CargoBuild and install Jolt from source.cargo --version
GitDownload the repository and manage source code.git --version
JDK 21 or compatibleCompile and run Java applications. Jolt can download Temurin when explicitly authorized.java --version

If no compatible JDK is installed, nothing is downloaded silently. Install one yourself or use --download-jdk with supported commands.

2. Install Jolt

From the repository with Cargo

git clone https://github.com/Escobarq/jolt.git
cd jolt
cargo install --path .

This installs jolt into Cargo's binary directory. If the terminal cannot find it, add that directory to PATH and open a new terminal.

Windows

From the repository root, you can also generate the official installer:

pwsh scripts/build-windows-installer.ps1

The installer configures Jolt in the user PATH. The final format depends on the tools available in your environment.

3. Check version, help, and environment

Run these checks immediately after installation. This confirms which executable you are using and shows the options supported by your version.

jolt --version
jolt --help
jolt check
jolt init --help
CommandWhat it shows
jolt --versionThe installed CLI version.
jolt --helpAvailable commands.
jolt <command> --helpArguments and flags for one command, such as jolt package --help.
jolt checkThe state of Java, Rust, cache, and the current project.

4. Create your first project

jolt init my-project --template cli --package com.example.app
cd my-project

my-project is the folder name and com.example.app is the root Java namespace. To list the available templates:

jolt init --list-templates

Included templates are minimal, cli, javafx, swing, web, and spring. For example, replace cli with javafx.

5. Add dependencies

Use a normal dependency at runtime. For JUnit, Mockito, or other tools used only during development, add --dev:

# Runtime dependency
jolt add com.google.code.gson:gson

# Development/testing dependency
jolt add org.junit.jupiter:junit-jupiter-api:5.11.0 --dev

# Resolve and download dependencies
jolt install

Jolt writes coordinates to jolt.toml and updates jolt.lock. Review both files and keep the lockfile under version control.

6. Daily workflow

# Run the application
jolt run

# Run and restart when files change
jolt run --watch

# Pass arguments to the Java application
jolt run -- --profile dev

# Run tests
jolt test

# Build a standalone Fat-JAR
jolt build --standalone

# Verify compilation, tests, and startup
jolt verify

If the project needs a JDK download, authorize it explicitly:

jolt run --download-jdk
jolt test --download-jdk
jolt build --standalone --download-jdk
