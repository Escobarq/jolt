Referencia del CLI

Esta página documenta los comandos que acepta el ejecutable jolt, incluidos sus aliases, flags cortos, valores y defaults.

Fuente de verdad: la ayuda de tu instalación siempre tiene prioridad. Consulta jolt --version y jolt <comando> --help si tu versión difiere.

Sintaxis y ayuda

jolt <comando> [opciones] [argumentos]
jolt --version
jolt --help
jolt build --help

Los argumentos posicionales son obligatorios salvo que se indique lo contrario. Un flag booleano se activa al escribirlo; no recibe true o false.

Agregar una dependencia paso a paso

Usa groupId:artifactId para dejar que Jolt resuelva la versión, o añade :version para fijarla explícitamente. El flag --dev (-D) coloca la dependencia en [dev-dependencies]; no es lo mismo que una dependencia de runtime.

# Runtime: se necesita al ejecutar la aplicación
jolt add com.google.code.gson:gson

# Desarrollo/pruebas: se agrega a [dev-dependencies]
jolt add org.junit.jupiter:junit-jupiter-api:5.11.0 --dev
# La forma corta equivalente:
jolt add org.junit.jupiter:junit-jupiter-api -D

# Verifica que quedó en el archivo correcto
Select-String -Path jolt.toml -Pattern "dev-dependencies|junit"

Después de agregarla, ejecuta jolt install para resolver y descargar el árbol de dependencias. Jolt actualiza jolt.toml y genera o actualiza jolt.lock; conserva ese lockfile en control de versiones.

jolt add org.junit.jupiter:junit-jupiter-engine:5.11.0 --dev
jolt install
jolt test
¿Qué comando debo usar? Usa una dependencia normal para librerías que tu aplicación necesita en producción; usa --dev para JUnit, Mockito, herramientas de análisis o cualquier librería usada solo durante desarrollo y pruebas.

Dependencias dentro de un workspace

Desde la raíz de un workspace, indica el módulo con --member (o su alias --pkg). El módulo debe existir en el manifiesto del workspace.

# Dependencia de runtime del módulo api
jolt add com.fasterxml.jackson.core:jackson-databind --member api

# Dependencia de pruebas del módulo api
jolt add org.junit.jupiter:junit-jupiter-api:5.11.0 --dev --member api

# Instalar todos los módulos
jolt install --all

Buscar y eliminar

# Buscar coordenadas en Maven Central (10 resultados por defecto)
jolt search junit
jolt search junit --limit 20

# Eliminar una dependencia; no se incluye la versión
jolt remove com.google.code.gson:gson
# Alias equivalente
jolt rm com.google.code.gson:gson

Importante: remove recibe solo groupId:artifactId. Si la dependencia pertenece a un módulo, repite el selector: jolt remove org.junit.jupiter:junit-jupiter-api --member api. No existe un comando separado para “actualizar”: cambia la versión en jolt.toml y vuelve a ejecutar jolt install.

Build y empaquetado

ComandoFlagsValores / resultado

-o, --output <DEST> (alias --dest)

-i, --icon <PATH>

-p, --member <MEMBER> (alias --pkg)
--verbose		TYPE: msi, app-image, nsis o exe. Default: app-image (Windows: msi). DEST default: dist/. SCOPE: per-user o per-machine.
jolt package --type nsis --output dist --main-class com.example.Main --verbose

package también acepta los aliases pkg y bundle. En build, --package delega en el empaquetado nativo; no debe confundirse con el argumento --package de init.
