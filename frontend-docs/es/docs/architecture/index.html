Arquitectura

Joltv está construido en Rust y separa la experiencia de usuario, la resolución de dependencias, la compilación y el empaquetado en módulos especializados.

Visión general

CLI (clap)
  └── main.rs: orquesta el comando
       ├── core: manifiestos, lockfile y caché
       ├── resolver: Maven Central y POMs
       ├── build: javac, ejecución y JUnit
       ├── packaging: JAR, jpackage e instaladores
       ├── toolchain: detección y descarga de JDK
       ├── scaffold: templates y configuración IDE
       └── doctor: diagnóstico del entorno

Módulos principales

MóduloResponsabilidadArchivos clave
coreTipos canónicos y persistencia.manifest.rs, lockfile.rs, cache.rs
cliComandos, argumentos y flags.args.rs, mod.rs
buildCompilación, ejecución y pruebas.compiler.rs, runner.rs, test_runner.rs

packagingArtefactos distribuibles.jar.rs, jpackage.rs
toolchainJDKs locales y remotos.detector.rs, downloader.rs

Flujo de ejecución

  1. Clap analiza el comando y sus opciones.
  2. El manifiesto se carga desde el directorio actual o el workspace raíz.
  3. El toolchain manager selecciona un JDK compatible.
  4. El resolver prepara dependencias y el build ejecuta las herramientas Java.
  5. El resultado se entrega en target/ o dist/.

Extender el CLI

Los nuevos comandos deben declarar su interfaz en src/cli/args.rs, mantener la lógica en el módulo de dominio adecuado y exponerse mediante su mod.rs. Evita colocar lógica de compilación o empaquetado directamente en main.rs.
